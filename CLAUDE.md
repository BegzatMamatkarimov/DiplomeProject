# SPS: Student Performance System

Интеллектуальная информационно-аналитическая система мониторинга успеваемости и достижений студентов с ИИ-ассистентом. Дипломный проект на заказ.

**Источник истины:** папка `docs/`. Перед любой фичей читай `docs/product-brief.md` и `docs/data-model.md`. Если требование противоречит документам, остановись и спроси, ничего не придумывай.

## Сроки
- MVP: показ заказчику ~14.11.2026. План по этапам в `docs/mvp-plan.md`, без привязки к дням: чем быстрее, тем лучше.
- Полная версия: до января 2027.

## Стек (решения в `docs/decisions.md`)
- Next.js (App Router) + TypeScript (strict)
- Tailwind CSS + shadcn/ui, тёмная и светлая тема (next-themes)
- Prisma + PostgreSQL (локально через `docker compose`)
- Auth.js (credentials), роли: STUDENT, TEACHER, ADVISOR, DEAN
- next-intl: ru (по умолчанию), kk, en
- Recharts для графиков
- ИИ: слой провайдеров с OpenAI-совместимым API (Gemini, Groq, OpenRouter), см. `docs/ai-assistant.md`
- Основа: форк Lama Dev School Management Dashboard. Clerk заменён на Auth.js, роль parent заменена на advisor.

## Команды
```bash
docker compose up -d        # PostgreSQL
npm run dev                 # http://localhost:3000
npx prisma migrate dev      # миграции
npx prisma db seed          # демо-данные
npm run lint && npm run typecheck
```

## Правила кода
- Идентификаторы, комментарии и коммиты на английском. Тексты интерфейса только через ключи next-intl, без хардкода строк в JSX.
- Сервер: Server Actions или Route Handlers. Валидация входных данных через zod.
- **Доступ проверяется на сервере** в каждой action или query через `requireRole()`:
  - студент видит только свои данные;
  - эдвайзер видит только студентов своей группы;
  - преподаватель видит только свои предметы;
  - деканат видит всё.
- Не плодить зависимости. Новый пакет добавляем только с объяснением в PR или коммите.
- UI: компоненты shadcn/ui. Стиль минималистичный, как у Linear и Vercel: много воздуха, нейтральная палитра, один акцентный цвет, без градиентного «пафоса».
- Числа (GPA, баллы, пороги риска) не хардкодить: брать из настроек (`Setting` или `GradeScale`).

## Рабочий процесс
1. Планирование в plan mode (модель Opus). План сверить с `docs/`.
2. Реализация небольшими шагами (Sonnet). После каждого шага: `lint`, `typecheck`, проверка в браузере.
3. Агенты проекта: `sps-architect` (план), `sps-implementer` (код), `sps-reviewer` (проверка доступа, i18n и соответствия ТЗ).
4. Один коммит на одну законченную подзадачу. После завершённого этапа MVP обновляй `docs/progress.md`: что сделано, скриншоты, отклонения от плана.
5. Документацию для автора диплома (`docs/thesis-notes/`) пополняй по ходу: архитектура, схемы, алгоритмы риска и рейтинга.

## Не делать
- Не писать произвольный SQL из ответов ИИ. Ассистент работает только через типизированные tools (см. `docs/ai-assistant.md`).
- Не коммитить `.env` и ключи API.
- Не менять согласованный scope без вопроса.
