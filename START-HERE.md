# Как начать работу в Claude Code

## 1. Подготовка (один раз)
1. Найди оригинальный шаблон Lama Dev «next-dashboard-ui» на GitHub (вероятно, `safak/next-dashboard-ui`). Посмотри лицензию.
2. Сделай fork в свой аккаунт или создай новый приватный репозиторий `sps` и залей туда код шаблона.
3. Склонируй локально, скопируй в корень содержимое этого пакета (`CLAUDE.md`, `docs/`, `.claude/`).
4. Установлены Docker Desktop и Node.js 20+.
5. Получи бесплатный ключ Gemini в Google AI Studio (понадобится на этапе 5). Ключ Groq — как запасной.

## 2. Запуск Claude Code
```bash
cd sps
claude
```
- `/model` → выбери `opusplan` (планирование на Opus, код на Sonnet). Уже прописано в `.claude/settings.json`; проверь, что применилось.
- `/agents` → проверь, что видны `sps-architect`, `sps-implementer`, `sps-reviewer`.
- `/mvp-stage 1` → запуск первого этапа.

## 3. Первое сообщение (если не хочешь команду)
```
Прочитай CLAUDE.md и всё в docs/. Это форк шаблона Lama Dev.
Сначала изучи текущую структуру репозитория и составь короткий отчёт:
что в шаблоне есть, что совпадает с нашей моделью данных, что удаляем, что переделываем.
Проверь лицензию. Потом запусти /mvp-stage 1.
```

## 4. Ритм работы
- Один этап = одна сессия. Между этапами `/clear`: контекст чистый, память даёт `CLAUDE.md` и `docs/progress.md`.
- Каждый план одобряешь ты. Код не пишется, пока план не одобрен.
- Закрыл этап → сразу `/mvp-stage N+1`. Привязки к дням нет.
- Коммит после каждой подзадачи, push в конце этапа.

## 5. Когда что брать из установленных плагинов
| Задача | Что использовать |
|---|---|
| Спорное архитектурное решение | Engineering → `architecture` (ADR), записать в `docs/decisions.md` |
| Тесты для GPA, рейтинга, риска | Engineering → `testing-strategy`; агент TDD из ECC, если установлен |
| Ревью перед показом | `sps-reviewer` + Engineering → `code-review` |
| Ошибка, которую не получается понять | Engineering → `debug` |
| Документация для автора диплома | Engineering → `documentation` → `docs/thesis-notes/` |

У ECC есть свои агенты с похожими ролями (planner, code-reviewer и др.). Чтобы не путаться, для этого проекта планируем и ревьюим через `sps-*`: они знают наши документы.
