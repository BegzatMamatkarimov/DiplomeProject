# План MVP по этапам

Сроков по дням нет: следующий этап начинаем сразу, как закрыт предыдущий. Цель — MVP как можно быстрее, показ заказчику не позже ~14.11.2026.

Каждый этап: plan mode → реализация → ревью → коммит → `docs/progress.md`.

## Этап 1. Фундамент
- Форк шаблона Lama Dev: найти оригинальный репозиторий, **проверить лицензию**, удалить лишнее (parent, lessons, exams, если не нужны).
- `docker-compose.yml` с PostgreSQL, `.env.example`.
- Prisma-схема по `docs/data-model.md` (без полей из «полной версии»), миграция.
- Seed с демо-данными.
- Заменить Clerk на Auth.js (credentials), роли и `requireRole()`, middleware маршрутов `/student`, `/teacher`, `/advisor`, `/dean`.
- ✅ Готово, когда: вход под четырьмя демо-логинами ведёт на свой дашборд.

## Этап 2. Дизайн-система и каркас
- shadcn/ui, токены цветов, шрифт (Inter или Geist), next-themes с переключателем.
- next-intl: ключи ru (kk и en пока копии ru).
- Layout: сайдбар по роли, топбар (тема, язык, профиль).
- Страница входа в стиле Vercel и Linear.
- ✅ Готово, когда: каркас выглядит «дорого», тема переключается.

## Этап 3. Успеваемость студента
- Дашборд студента: карточки GPA, посещаемость, место в рейтинге, риск.
- Таблица оценок по предметам, график динамики GPA по семестрам.
- Рейтинг группы с фильтром GPA / GPA_PLUS.
- ✅ Готово, когда: цифры сходятся с seed (проверить вручную на 1–2 студентах).

## Этап 4. Достижения и хакатоны
- Студент: список, форма добавления (тип HACKATHON показывает поля команды, проекта и GitHub), загрузка сертификата (локально в `/uploads`).
- Эдвайзер: очередь на подтверждение, approve или reject с комментарием, баллы выставляются автоматически.
- Деканат: CRUD каталога мероприятий.
- ✅ Готово, когда: подтверждённый хакатон меняет место студента в режиме GPA_PLUS.

## Этап 5. ИИ-ассистент
- LLMProvider (Gemini по умолчанию + Groq фолбэк), AssistantService, tools из `docs/ai-assistant.md`.
- UI чата (боковая панель или страница), стриминг ответа, история сессий.
- ✅ Готово, когда: на вопрос «Как мне поднять рейтинг?» ассистент отвечает по реальным данным студента и советует мероприятия из каталога.

## Этап 6. Роли преподавателя, эдвайзера, деканата
- Преподаватель: свои предметы, ввод оценок и посещаемости (простая таблица), список студентов с риском.
- Эдвайзер: своя группа, риск, достижения.
- Деканат: аналитика по группам (средний GPA, посещаемость, доля риска, топ достижений), графики.
- ✅ Готово, когда: у каждой роли есть осмысленный дашборд.

## Этап 7. Полировка и демо
- Пустые состояния, загрузки, ошибки, адаптив.
- README (запуск в 3 команды), скриншоты в `docs/screenshots/`.
- Сценарий демо (5 минут): студент → добавляет хакатон → эдвайзер подтверждает → рейтинг меняется → ассистент объясняет риск → деканат видит аналитику.
- ✅ Готово, когда: «чистый» запуск с нуля по README проходит без ошибок.

## Приоритеты
ИИ и хакатоны — суть заказа, поэтому они идут раньше остальных ролей. Если время поджимает, упрощаем этап 6 (деканат и преподаватель), потом полировку.
